## 一、已实证的关键事实（勿再重复验证）

宿主与消息契约：
- `TEngForm.SetOnWndProc` 接管后每条未处理消息必须 `m.InheritedWndProc(msg)`，否则卡死。
- `WM_ERASEBKGND` **首帧后抑制**（`s.Frame > 0` 才 `msg.Result = 1`），初始化期必须透传——无条件吞掉会初始化卡死（已试过、已回退，别再试）。
- `WM_TIMER/WM_PAINT` 是低优先级消息，持续 `WM_MOUSEMOVE` 会饿死它们 → 动画相位必须用墙钟 `PhaseNow()`，不能 `Phase += dt`。

渲染管线硬约束：
- 画刷必须**先 `SetColor(c)` 后 `SetStyle(style)`**（`SetColor` 会把 Style 重置为 BsSolid），否则 TextOut 画实心色块。
- 帧缓冲必须 `Pf24bit`；`Pf32bit` 的 ScanLine 直写可回读但 `Canvas.Draw` 不做 alpha 混合（GDI 只写 RGB、A=0）。
- `Pf24bit` 的 `ScanLine` raw buffer 与 GDI HDC **不同步**；批量读写用 `CreateIntfImage().PixelData()`（读）与 `LoadFromIntfImage`（写）。
- RGBA 透明层：`NewLazIntfImageWithIntX2RIQFlags(RiqfRGB|RiqfAlpha)` → `PixelData()` 整块写 BGRA → `LoadFromIntfImage` → `Pf32bit` → `Canvas.Draw`；通道 BGRA、stride=w×4。
- 不透明 `CopyRect`（≈0.5ms 全窗）与 alpha `Draw`（≈24.7ms）差 **50 倍**；禁止为 AA 叠额外 RGBA overlay 层。

帧调度契约（成熟框架模型，已落地并验证）：
- 帧泵 = `FrameScheduler`：绝对 60Hz 墙钟时间轴（`next += 1s/60`，慢帧跳槽不追帧），`PostMessageW(WM_APP+1)` 投递帧槽到主线程；最多 2 个 outstanding；`timeBeginPeriod(1)` 抬定时器精度；可复用 `time.Timer`。
- 每帧分 **PREPARE**（离屏批量光栅化整帧）/ **PRESENT**（帧边界 opaque `CopyRect` 原子提交）。
- 失效驱动：动画 60Hz；静止零帧；输入只标脏区不请求帧；鼠标移动不抬高 FPS（`--mousetest` 验证）。
- 静态层烘焙：9 张玻璃卡片 + 2 光斑 + 图例一次烘成 opaque `Pf24bit` 快照；每帧 memcpy 恢复（AA 模式从 `staticPx` Go 侧恢复）。

AA 契约（LCL `AntialiasingMode(AmOn)` 实测无效，灰阶像素为 0，勿再试）：
- 软件 coverage 光栅化：`raster.go` 的 `FramePixels` 绑定帧缓冲像素块，按覆盖率**就地** read-modify-write 混色。
- 折线/曲线是**单一图元**：描线期间覆盖率进缓冲取 **MAX**，`strokeEnd` 才混合一次；逐段圆帽 over 合成会产生周期性亮珠=锯齿。
- 发光 = `lineCov` **单遍**合并覆盖率（`core + glow − core·glow`），一次距离场算两档；两遍会把 180 点曲线成本翻倍。
- 文字**不能**进软件光栅器（丢 ClearType）：几何光栅化后用 `LoadFromIntfImage` 写回，再 GDI `TextOut` 回放 `textCmds`；`TextOut` 无裁剪，标签必须按 rect 宽度裁剪（`fitText` + 省略号）。
- 稀疏触碰索引 + 代际标记是覆盖率累积不涨帧成本的关键（第一版整块清零+按行扫描曾把 widgets 推到 7.06ms）。

布局与缓存契约（本轮新增，血泪教训）：
- 任何「按需重建」的缓存都要假设它**可能发生在 OnPaint 回调内部**（滑条 InvalidateStatic、WM_SIZE），必须显式声明后端归属：烘焙期间强制 `painter.frame = nil` 并恢复现场，否则 FillRect/文字写错缓冲——这就是「拖滑条第 9 卡内容消失 + resize 崩溃（fatal error: fault）」的共同根因。
- 由位图派生的 raw 像素视图必须与宿主同生命周期：**先 `freeAASurface()` 再 Free 旧 backBuf**，顺序反了就是悬空 DIB；读回长度必须按位图自身尺寸算（冷却期用新尺寸读旧尺寸 DIB 越界，第二次偶发崩溃）。
- 布局坐标与字号必须同一套缩放：`layout.go` 设计画布 1440×880 等比缩放 + 居中 + 整体上移 16px；字号/inset/行距乘 `Scene.S()`，否则窗口变小文字必溢出。
- resize 冷却：`WM_SIZE/WM_SIZING` 打时间戳，180ms 内 `holdStatic` 保留旧快照走轻量路径（9 张 RGBA 卡片烘焙 85–100ms，逐中间尺寸烘焙会 350ms 零帧）。
- **输入优先级（本次会话实证，勿再按 capture 方向排查）**：Win32 `GetMessage` 顺序是 sent → posted → 硬件输入 → WM_PAINT → WM_TIMER；`PostMessageW(WM_APP+1)` 的帧消息比鼠标/键盘/标题栏输入优先级高。帧泵必须只保留 1 个 outstanding、闭环等 `FrameDone`；「3 槽没回就清零 inflight」的丢包看门狗在长帧/重烘焙时会灌满队列，是「最大化后输入全死」的直接原因。2880×1557 单帧 ≈30ms（超 16.67ms 预算），最大化后静态重烘焙 ≈190ms。
- **模态循环与 capture**：真实 `SendInput` 拖边框能正常进出模态循环，`GetCapture()` 全程为 0；但 LCL 会**静默**释放 `MouseCapture`（不保证发 `WM_CAPTURECHANGED`），`Scene.capture` 可能残留。自愈要用 `GetAsyncKeyState(VK_LBUTTON)` 判断真实按键，不能只靠 MouseUp / `WM_CAPTURECHANGED`。

6. **（后续会话追加）修掉「调整大小/最大化后标题栏、还原、鼠标全失效但图形还在渲染」**，根因与修复见第三节；新增 `--inputdiag` / `--inputtest` 与 22 项回归断言。

## 三、✅ 已解决：调整大小 / 最大化后输入全部失效（后续会话实证）

**结论：原交接文档怀疑的「capture 永不清除」不是主因；真正根因是帧消息队列把输入饿死了。** 先加 `--inputdiag` / `--inputtest` 拿证据，没有猜。

**证伪 capture 假设**：最大化状态下 `osCapture=0x0`、`lclCapture=false`、`sceneCapture=nil`，`WM_NCHITTEST(caption)` 用 `SendMessage` 立刻返回 `HTCAPTION(2)`；真实 `SendInput` 拖边框可正常进出模态循环并收到 `WM_CAPTURECHANGED`。布局 `relayout` 也正常（scale 1.000→1.769→1.000）。

**决定性 A/B**：同一最大化状态下注入一次点击，派发延迟 **帧泵开 382ms / 帧泵关 14ms（25 倍）**；点「切换主题」`light -> light` FAIL。sent 消息能过、posted/硬件输入过不去 → Win32 消息优先级问题。

**根因链**：最大化后客户区 2880×1557（200% DPI），单帧 ≈30ms > 16.67ms 预算 → 旧帧泵允许 2 个 outstanding 且每槽无条件再投，post 队列永不为空；「3 槽没 `FrameDone` 就清零 inflight」的伪丢包看门狗又在 ~190ms 静态重烘焙期间反复触发、灌入几十条帧消息 → `GetMessage` 永远取不到鼠标/键盘/NC 消息，但 `WM_APP+1` 持续被处理（图形继续渲染）。

**修复**：`framescheduler.go` 改为单 outstanding 闭环（`CAS(0,1)` 拒绝二次投递、`waitConsumed()` 等 `FrameDone`、慢帧平移时槽而非丢整槽）、删掉 3 槽伪丢包看门狗（改 3s 病理超时）、超预算帧后留 1.5ms 空队列窗口让输入被取走、`FrameDone(costUs)` 回报真实帧耗时、暂停后投递前复查 active；`main.go` 在取消类消息清 capture；`scene.go` 加 `releaseStaleCapture` + `GetAsyncKeyState` 硬件按键自愈（修掉诊断顺带发现的次生问题：模态循环吞掉 MouseUp 后 LCL 静默释放 capture，滑块会永远跟着鼠标改不透明度）。

**闭环泵的两个连带问题也一并修掉**：① LCL `Repaint = Invalidate + Update` 会额外留下一条低优先级 `WM_PAINT`，旧代码按 OnPaint 计数，闭环队列让它在暂停期到达 → `--schedtest` 偶发「静止期 24 帧」；改为**帧 = 一个帧槽**（`RenderFrame()` 里计数 + FPS 统计），静止严格零帧。② `--schedtest` 的 1s 窗口起点落在窗口创建/首次烘焙里（WM_ACTIVATE ~500ms 才到），外部 CPU/杀软顿挫会造成 12–39 FPS 假 FAIL；改为先等 30 帧、动画段 2s、判据用两段合并的**帧间隔中位数**（14–20ms，≥100 样本），绝对帧数只打印不判定。

**实测**：最大化下点击延迟 **16–32ms**（关泵 3–4ms），22 项 `--inputtest` 断言连跑 3 次全 PASS；`--bench` 60.0–60.4 FPS、`--schedtest` ×8 全 PASS（暂停 0 帧、合并帧间隔中位数 16.5–17.1ms）、`--mousetest` ×3 全 PASS、`--resizetest` / `--selftest` / `go test` / 全部 WG_* A/B 全 PASS。详见 `showcase/README.md` 第九节、`wg/README.md` 契约 ⑪⑫。

**残留限制（未解决，但已不影响输入）**：最大化瞬间主线程仍要烘焙一次 2880×1557 静态快照（~190ms），有一次可感知顿挫；生产后端应做 DPI 降采样烘焙或改 GPU 合成。
